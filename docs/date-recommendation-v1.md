# 데이트 코스 추천 시스템 v1

## 목표

두 사람 중 한 명만 만족하는 인기 장소가 아니라, 둘의 최소 만족도를 지키면서 현재 날짜·시간·예산·이동 조건에 맞는 2~3개 장소 코스를 추천한다. 추천 결과에는 선택 이유와 주의할 조건을 함께 보여준다.

## 입력 데이터

- 개인 취향: 음식, 활동, 분위기, 예산, 이동, 시간, 선물
- 강한 제한: 알레르기, 절대 비선호, 최대 예산, 최대 이동 시간, 접근성
- 요청 상황: 날짜와 시작 시간, 출발 지역, 교통수단, 총 소요 시간, 실내·실외 선호
- 후보 장소: 카테고리, 위치, 영업시간, 가격대, 태그, 신뢰도
- 피드백: 저장, 건너뛰기, 실제 방문, 만족도, 다시 추천하지 않기

소곤.zip의 비공개 본문은 추천 입력으로 직접 사용하지 않는다. 사용자가 동의한 취향 태그만 별도로 저장해 추천에 사용한다.

## 추천 순서

1. 알레르기, 영업시간, 예산, 거리처럼 반드시 지켜야 하는 조건으로 후보를 먼저 제외한다.
2. 남은 장소에 대해 두 사람 각각의 취향 일치도를 0~1로 계산한다.
3. 두 사람의 낮은 쪽 만족도를 크게 반영해 한쪽 희생이 반복되지 않도록 한다.
4. 이동 시간과 장소 간 동선을 계산해 2~3개 장소를 하나의 코스로 조합한다.
5. 비슷한 장소만 반복되지 않도록 다양성 재정렬을 적용한다.
6. “둘 다 조용한 분위기를 선호하고, 예산과 이동 범위 안에 있어요”처럼 추천 이유를 생성한다.

초기 점수식 예시는 다음과 같다.

```text
공동 점수 =
  0.35 × min(사용자 A 일치도, 사용자 B 일치도)
  + 0.25 × 두 사람 평균 일치도
  + 0.15 × 날짜·시간·날씨 등 상황 일치도
  + 0.10 × 새로운 경험 점수
  + 0.10 × 장소 정보 신뢰도
  + 0.05 × 이동 편의성
```

가중치는 실제 저장·방문·만족 피드백을 모은 뒤 조정한다.

## 데이터 모델 제안

- `preference_signals`: 사용자별 구조화 취향과 강도, 강한 제한 여부
- `recommendation_requests`: 날짜, 지역, 예산, 시간, 교통수단
- `recommendation_candidates`: 요청별 후보, 점수 구성, 제외 사유
- `recommendation_feedback`: 노출, 저장, 건너뛰기, 방문, 만족도

현재의 자유 입력 `preferences`는 유지한다. 저장 시 규칙 기반 키워드 추출로 먼저 구조화하고, 모호한 문장만 LLM으로 태그 후보를 제안한다. LLM은 알레르기나 영업시간 같은 필수 조건 판정과 최종 필터링을 맡지 않는다.

## API 제안

- `POST /api/recommendations/generate`: 연결된 두 사람과 요청 상황을 기준으로 코스 생성
- `POST /api/recommendations/:id/feedback`: 저장·건너뛰기·방문·만족도 기록
- `GET /api/recommendations/history`: 이전 추천과 피드백 조회

## 단계별 출시

1. 규칙 기반 MVP: 운영자가 검수한 소규모 장소 데이터와 현재 취향 입력으로 점수 계산
2. 장소 데이터 연동: 지도 제공자의 검색, 위치, 영업시간, 가격대 정보를 정규화
3. 학습형 개선: 저장·방문·만족 피드백으로 개인별 가중치와 다양성 조정

MVP 성공 기준은 추천 저장률, 두 사람 모두의 만족도, 제한 조건 위반률, 같은 유형 반복률로 측정한다.
