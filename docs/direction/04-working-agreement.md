# 작업 규칙 (Claude · Codex 공통)

> 진웅만 고친다. 에이전트는 이 규칙을 따르고, 규칙이 작업을 막으면
> 우회하지 말고 `05-open-questions.md`에 적는다.

## 시작 전

1. `00-product.md`의 절대 규칙을 읽는다.
2. `02-roadmap.md`에서 지금 트랙을 확인한다. **거기 없는 걸 임의로 시작하지 않는다.**
3. 설계를 바꿀 거면 `03-decisions.md`를 먼저 본다. 이미 논의된 걸 다시 뒤집지 않는다.

## 검증

**끝났다고 말하기 전에 반드시 돌린다.**

```bash
yarn verify   # typecheck + test + build
```

- 테스트가 깨지면 **테스트를 고치는 게 아니라** 왜 깨졌는지 본다.
  `scripts/test.mjs`에 있는 건 전부 깨지면 조용히 사고가 되는 항목이다.
- 절대 규칙을 건드리는 변경이면 코드를 멈추고 물어본다.
- 새 도메인 규칙을 만들었으면 테스트도 함께 추가한다.

DB 스키마를 바꿨으면 임시 sqlite에 0001부터 순서대로 적용해서 실제로 도는지 확인한다.

## 보고

**했다고 말한 것만 했다고 한다.** 특히:

- 테스트가 실패했으면 실패했다고 출력과 함께 말한다.
- 건너뛴 부분이 있으면 무엇을 왜 건너뛰었는지 말한다.
- 검증 못 한 값(임계값, 가중치 같은 감으로 정한 숫자)은 "미검증"이라고 명시한다.
- 확인 안 한 걸 "확인했다"고 쓰지 않는다.

## 스코프

- 요청받은 범위를 조용히 넓히거나 줄이지 않는다.
- 지나가다 발견한 문제는 고치지 말고 **말한다**. 고쳐야 할 것 같으면 물어본다.
- 대규모 리팩터링은 요청받았을 때만 한다. `FE/App/mobile/src/App.tsx` 분리도 마찬가지다.

## 코드

- 주변 코드의 스타일·주석 밀도·네이밍을 따른다.
- 주석은 **왜**를 적는다. 무엇을 하는지는 코드가 말한다.
  특히 "이렇게 안 하면 무엇이 깨지는가"를 남긴다.
- UI 텍스트는 한국어다.
- BE에 엔드포인트를 추가하면 `functions/`에 어댑터도 추가한다. 빠뜨리면 배포 후 404다.
- 새 마이그레이션을 만들면 `BETA_DEPLOY.md`와 `SOGONZIP.md`의 목록도 갱신한다.

## 문서

작업이 끝나면:

- `02-roadmap.md`의 체크박스와 상태를 갱신한다.
- 설계 판단을 했으면 `03-decisions.md`에 결정·이유·포기한 것을 추가한다.
- **대화에만 남은 결정은 없는 것과 같다.** 다른 에이전트는 그 대화를 볼 수 없다.

## git

- 커밋·푸시는 진웅이 요청할 때만 한다.
- `main`에서 작업 중이면 브랜치를 먼저 판다.
- 커밋 메시지는 한 줄 요약 + 어느 영역(FE/BE/shared/docs)이 왜 바뀌었는지.

## 에이전트가 둘이라서 생기는 것

같은 파일을 동시에 만질 수 있다. 그래서:

- **작업 시작 전 `git status`를 본다.** 예상 못 한 변경이 있으면 덮어쓰기 전에 말한다.
- 큰 작업은 한 번에 하나의 영역만 만진다. FE와 BE와 마이그레이션을 동시에 뒤집지 않는다.
- 다른 에이전트가 만든 코드를 "정리"하지 않는다. 이상해 보이면 `05`에 적는다.
  `03-decisions.md`에 이유가 적혀 있을 수도 있다.
