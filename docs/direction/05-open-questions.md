# 미결 질문

진웅이 답해야 풀리는 것들. 에이전트는 여기에 질문을 추가하고,
**그 답에 의존하지 않는 작업은 먼저 끝낸다.** 답이 나오면 `03-decisions.md`로 옮긴다.

---

## 추천 (지금 트랙)

### ~~Q1. 팝업 데이터를 어떻게 채울 것인가~~ → 답 나옴 (`03-decisions.md` #13)

공공 API로 기본 데이터를 만들고, 팝업은 검색·수동 큐레이션으로 보강한다.
Instagram 화이트리스트는 1단계에서 뺀다. (`../date-course-data-strategy.md`)

### Q2. 베타에서 추천을 실제로 켤 것인가

장소 데이터가 200건뿐이면 추천 품질이 낮다. 그래도 켜야 로그가 쌓인다.

- 켠다: 데이터는 모이지만 첫인상이 나쁘다
- 안 켠다: L0 졸업 조건(로그 수집)을 영원히 못 채운다
- 절충: 친구 2~3커플에게만 "아직 실험 중"이라고 알리고 연다

### Q3. 취향 온보딩을 넣을 것인가

지금 `preferences`가 5개 미만이면 랭킹이 사실상 무작위다.
이미지 2지선다 10문항으로 초기 태그 벡터를 확보하는 안이 있다
(`date-recommendation-v2-ai.md` §5(b)). 만드는 비용이 작지 않다.

### ~~Q4. 서비스 지역을 어디로 한정할까~~ → 답 나옴 (`03-decisions.md` #13)

서울 핵심 상권 6곳: 성수 · 한남 · 연남/홍대 · 을지로 · 잠실 · 강남/신사.

### Q5. 병합 임계값 50m / 2km이 맞나

감으로 정했다. 실제 장소 200건을 넣어보고 조정해야 한다. (`03-decisions.md` #7)

## 제품

### Q6. 커플과 친구를 동시에 지원할 것인가, 커플부터 할 것인가

`relationship_type`은 이미 있지만 실제로 다르게 동작하는 부분이 없다.
추천 로직은 둘이 꽤 다를 수 있다 (친구는 예산·거리 제약이 더 느슨하다).

### Q7. 최고 민감도 파일은 "추천에 반영하기"를 기본 꺼둘 것인가

지금은 `recommendation_on` 기본값이 1이다. 민감한 내용일수록 취향 반영도 조심스러운 게
맞을 수 있는데, 그러면 추천 데이터가 더 줄어든다.

### Q8. 열림 시점을 달력 날짜 기준으로 갈 것인가, 관계 D+ 기준으로 갈 것인가

지금은 둘 다 지원한다(`100일 후`는 D+, `직접 날짜 선택`은 달력).
UI에서 하나를 주(主)로 밀어야 한다면 어느 쪽인가.

## 운영

### Q9. 베타 계정을 친구가 직접 만들게 할 것인가, 진웅이 미리 만들어줄 것인가

### Q10. 운영자가 베타 데이터를 어디까지 볼 수 있어야 하는가

절대 규칙상 소곤파일 본문은 못 본다. 그럼 무엇을 봐야 운영이 되는가 —
가입 수, 연결 수, 파일 개수, 추천 저장률 정도인가.
