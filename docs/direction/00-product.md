# 제품 정체성과 절대 규칙

> 이 파일은 진웅만 고친다. 에이전트는 여기에 어긋나는 코드를 쓰지 않고,
> 어긋나야 할 이유가 생기면 코드를 쓰기 전에 물어본다.

## 한 줄

소곤.zip은 가까운 사람과 취향·마음·작은 비밀을 안전하게 저장하고,
**정해둔 시점에 열어보는** 관계 기반 아카이브다.

## 이 제품이 아닌 것

- 메신저가 아니다. 실시간 대화가 목적이 아니다.
- 일반 SNS가 아니다. 공개 대상은 연결된 **한 명**뿐이다.
- 데이트 코스 앱이 아니다. 추천은 아카이브에서 파생된 기능이지 그 반대가 아니다.

세 번째가 특히 중요하다. 추천 기능이 커지면 제품이 "또 하나의 맛집 앱"이 된다.
추천은 **"둘의 취향을 알고 있다"**는 아카이브의 자산을 쓰는 기능일 때만 의미가 있다.

## 절대 규칙 (P0)

깨지면 조용히 프라이버시 사고가 되는 것들이다. `scripts/test.mjs`가 자동으로 지킨다.
**이 규칙을 건드리는 변경은 테스트를 함께 고치는 게 아니라, 변경을 멈추고 물어본다.**

### 1. 열지 않은 소곤파일 본문은 상대에게 절대 보이지 않는다

- 상대에게 보이는 건 `status='opened'`인 파일뿐이다.
- 작성자만 자기 파일 전부를 본다.
- API 응답, 추천 결과, 로그, 에러 메시지 어디에도 미개봉 본문이 실리면 안 된다.

### 2. 소곤파일 본문은 추천 입력으로 쓰지 않는다

- `sogon_files.content`는 어떤 피처에도, 어떤 프롬프트에도 들어가지 않는다.
- 추천은 사용자가 **동의해서 따로 입력한** 취향(`preferences` → `preference_signals`)만 쓴다.
- 학습 데이터를 외부(Colab 등)로 내보낼 때는 `room_id` / `member_id`를 해시로 치환한다.

### 3. 열림은 항상 명시적이다

- 날짜가 됐다고 자동으로 내용이 공개되지 않는다. `ready`가 될 뿐이고, 여는 건 작성자다.
- "열림 시점"과 "추천 반영"은 화면에서도 코드에서도 분리한다.

### 4. 소곤폴더 정원은 2명이다

- 1:1 관계 제품이다. `ROOM_CAPACITY = 2`.
- 상대 동의(`connection_requests`) 없이 방에 합류할 수 없다.

### 5. 하드 제약은 점수로 상쇄되지 않는다

- 알레르기, 영업시간, 예산 상한, 최대 이동시간은 **필터**이지 가중치가 아니다.
- LLM이 이 판정을 대신하지 않는다. 규칙 코드로만 판단한다.

### 6. 운영자도 남의 소곤파일 본문은 못 본다

- `requireAdmin`을 쓰는 경로는 `places` 같은 **공개 데이터로 제한**한다.
- 베타 운영자가 진웅 한 명이어도 마찬가지다. 나중에 사람이 늘면 고치는 게 아니라 처음부터 그렇게 둔다.

## UX 원칙

- 한국어가 기본이다.
- 파일 / 폴더 / 압축(zip) 은유를 유지한다. "게시물", "피드" 같은 SNS 용어를 쓰지 않는다.
- 비공개 내용이 자동으로 공개되는 것처럼 **보이는** 화면도 만들지 않는다. 실제로 안 그래도 안 된다.
- 버튼은 무엇이 일어나는지 명확해야 한다. "확인" 대신 "이 파일 열기".

## 대상 사용자

연인 또는 아주 가까운 친구 1:1. 지금은 진웅의 친구들이 쓰는 무료 베타 단계다.
사용자 수가 아니라 **"둘 다 만족했는가"**가 성공 지표다.
