# 개발 방향성 (진웅 · Claude · Codex 공용)

사람 한 명과 에이전트 둘이 같은 코드베이스를 만진다. 각자 다른 세션에서 일하고
서로의 대화를 볼 수 없기 때문에, **합의된 내용은 반드시 이 폴더에 글로 남아야 한다.**
대화에만 있는 결정은 다음 세션에서 없는 것과 같다.

## 파일 구성

| 파일 | 내용 | 누가 고치나 |
|---|---|---|
| [`00-product.md`](./00-product.md) | 제품 정체성과 **절대 규칙**. 코드보다 우선한다. | 진웅만 |
| [`01-architecture.md`](./01-architecture.md) | 어디에 무슨 코드를 넣는가 | 합의 후 누구나 |
| [`02-roadmap.md`](./02-roadmap.md) | 지금 어디까지 됐고 다음은 무엇인가 | 작업 끝낸 사람이 갱신 |
| [`03-decisions.md`](./03-decisions.md) | 결정과 그 이유 (ADR) | 결정한 사람이 추가 |
| [`04-working-agreement.md`](./04-working-agreement.md) | 에이전트 작업 규칙 | 진웅만 |
| [`05-open-questions.md`](./05-open-questions.md) | 진웅이 답해야 풀리는 질문 | 누구나 추가, 진웅이 답 |

## 읽는 순서

**작업 시작 전 매번**: `00` → `02` → `04`
**설계를 바꾸려 할 때**: `03`을 먼저 본다. 이미 논의된 걸 다시 뒤집지 않기 위해서다.
**막혔을 때**: `05`에 질문을 추가하고, 그 질문에 의존하지 않는 부분을 먼저 끝낸다.

## 다른 문서와의 관계

- `SOGONZIP.md` — 저장소의 짧은 안내판. 이 폴더가 방향과 우선순위의 원문이다.
- `docs/reference/` — 현재 구현에서 참고하는 추천·데이터 상세 설계.
- `docs/archive/` — 현재 작업에 쓰지 않는 초기 초안·완료된 리뷰·디자인 입력 자료.
- `README.md` — 외부에 보여주는 소개. 방향성은 여기 쓰지 않는다.

## 규칙 하나

**이 폴더의 문서와 코드가 다르면, 둘 중 하나가 틀린 것이다. 그냥 지나치지 않는다.**
코드가 맞으면 문서를 고치고, 문서가 맞으면 코드를 고친다. 판단이 안 서면 `05`에 적는다.
